# ECE7128 · 공간지능특론

SPARO Lab 공간지능특론의 논문 리스트와 팀 프로젝트 페이지입니다.

## 동작

1. 학생이 페이지 안에서 논문 제목, 학회, 연도, 연구 주제, 링크를 입력합니다. 가입이나 등록 코드는 필요하지 않습니다.
2. 등록 서버가 입력을 검증하고 이 저장소의 `data/submissions.json`만 갱신합니다.
3. 등록한 학생의 화면에는 바로 반영됩니다. 다른 방문자는 등록 서버에서 최신 목록을 읽습니다.
4. 목록 변경 커밋마다 정적 사본도 자동으로 다시 배포합니다.

PDF나 첨부 파일을 업로드하지 않습니다. 학생에게 GitHub 계정·조직 가입·저장소 쓰기 권한을 요구하지 않습니다. 커밋은 서버에 연결한 인증 계정으로 기록되며 학생을 커밋 작성자로 지정하지 않습니다.

## 논문 검색

- 관심사, 연구 주제, 학술대회·저널, 연도, 저자, 소속, 키워드 조건을 함께 적용합니다.
- 페이지당 10·20·50·100편을 선택할 수 있으며 기본값은 20편입니다.
- 새 논문에는 저자·발표 당시 소속·키워드를 선택적으로 입력합니다.
- `site/bibliography.json`에 Crossref 및 OpenAlex에서 제목이 일치한 서지정보와 출처를 보관합니다. 원래 목록은 유지하며 빌드 시 결합합니다. 현재 341편 중 저자 정보 297편, 소속 정보 290편이 있습니다. 외부 서지정보에 누락이 있을 수 있으며, 정보가 없는 논문은 해당 필터로 검색되지 않습니다. 소속은 논문에 연결된 authorship 자료를 사용합니다.
- 수동 갱신: `python3 scripts/enrich-bibliography.py` (공개 API 조회, 기존 항목 재사용).

## 관심사 안내와 논문 카드

- 관심사를 누르면 한국어 안내와 영어 세부 키워드가 펼쳐집니다. 관심사와 세부 키워드는 기존 필터와 함께 적용됩니다. 관심사를 바꾸면 세부 선택은 초기화됩니다.
- 논문 카드는 저자·소속·짧은 요약을 같은 순서로 표시합니다. 확인된 저자·소속이 없으면 정보 없음을 표시하며 임의로 생성하지 않습니다. 이름/기관을 누르면 현재 검색 조건에 해당 필터가 적용됩니다.
- 기존 요약 30편은 보존했습니다. `site/summaries.json`은 나머지 310편의 짧은 소개를 보관합니다. 309편은 제목에 명시된 문제·방법을 정리했고, 제목만으로 방법을 알기 어려운 iSLAM 1편은 공개 초록을 근거로 작성했습니다. 이는, 논문 전문 분석이나 성능 평가가 아닙니다. 근거 제목·원본 행·서지 출처를 함께 저장하며 빌드 시에만 결합합니다.

## 구성

- 기본 논문 340편과 기존 검색·양식 화면.
- `server/handler.mjs`: 서버 전용 GitHub 기록 처리기. 저장소와 파일 경로를 코드에서 고정합니다.
- 중복 제목 방지, 동시 수정 충돌 재시도, 입력 길이·URL 검증.
- 팀 등록 화면도 유지하며, 수정 키는 등록 브라우저에 보관합니다. 공개 데이터에는 키 원문을 넣지 않습니다. 브라우저 저장소를 지우면 담당자를 통해 수정해야 합니다.
- `npm test`: 모의 GitHub API 검증. 실제 GitHub에 테스트 데이터를 올리지 않습니다.
- `npm run build`: GitHub Pages용 `_site/` 생성.

**GitHub Pages와 등록 서버 연결을 완료했습니다.** 페이지에서 논문과 팀 정보를 등록하면 이 저장소에 저장됩니다. 서버에 연결할 수 없을 때에는 마지막 정적 목록을 표시하고 등록 버튼을 비활성화합니다. `COURSE_PAGES_ENABLED=true`로 자동 배포를 켰습니다.

2026-10-18 실제 논문 등록(201), 브라우저 중복 등록 방지, 목록 341편 표시, GitHub Pages 자동 배포 성공을 확인했습니다. 저장소 전용 인증키는 2027-01-16 만료 예정입니다. 만료 전에 새 인증키를 서버 비밀 설정에 연결하고 다시 배포해야 합니다.

## 운영 연결

1. 기존 Sites 서버에 `server/handler.mjs`와 `server/sites-route.ts.example` 어댑터를 `/api/course-registry`로 연결합니다. 새 서비스 생성은 필요하지 않습니다. 공개 접근 전환은 승인되었습니다.
2. 서버 비밀 설정에 `GITHUB_CONTENTS_TOKEN`을 저장합니다. `sparolab/ece7128` 하나만 대상으로 한 fine-grained token, Contents read/write만 부여합니다. Workflows, Administration, 조직 전체 권한은 부여하지 않습니다. 토큰은 브라우저 코드·GitHub 저장소·채팅에 붙여넣지 않습니다.
3. `site/config.js`에 승인된 서버 주소를 지정합니다. 이 파일에는 비밀 값을 넣지 않습니다.
4. 이 저장소에서 GitHub Pages의 GitHub Actions 배포를 활성화한 뒤 `COURSE_PAGES_ENABLED=true`를 설정합니다.
5. 배포와 실제 기록 동작을 검증합니다. 공개 주소는 `https://sparolab.github.io/ece7128/`입니다.

연구실 홈페이지 저장소는 수정하지 않으며 연결 메뉴도 추가하지 않습니다.

## 로컬 검증

`npm test && npm run build` 후 `node scripts/preview.mjs`를 실행합니다. 출력된 로컬 주소에서 코드 입력 없이 등록 흐름을 검증할 수 있습니다. 데이터는 메모리에만 저장되며 서버 종료 시 사라집니다.
